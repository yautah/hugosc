# scbase-editor 对抗审查与验收

## 范围修订

2026-10-15 再次按用户要求归纳为站点通用文章编辑 Skill：删除电影考据章节结构、固定比较图样式、具体素材名、关服专属叙事与指定历史稿件路径。将 `news-writing.md` 替换为 `article-editing.md`，覆盖资讯、攻略、专题及回顾；保留真实项目格式和资源解析约定，月度平衡作为独立按需流程。下方首版审查结果仅为历史记录，不作为当前任务规则加载。

2026-10-15 用户明确工作流为“稿件入 Obsidian → 用户二次编辑 → 用户手动执行 pub”。当前 Skill 已移除公众号发布子流程、远端草稿管理、同步摘要与发布器调用，入口和 UI 描述也已同步收缩。稿件检查器只做本地文档与资源检查，保留微信头部字段的格式兼容，不检查远端上传条件。下文是首版较大范围的历史审查记录，其中公众号操作部分不再属于当前 Skill。

审查日期为 2026-10-15。范围是项目内的 `skills/scbase-editor/` 与根目录 `AGENTS.md`；未修改现有文章、发布器或站点模板，未上传公众号或推送仓库。

## 设计依据

本会话的重复工作是资讯核验、中文写稿、Obsidian/Hugo 入库、月度平衡更新、配图排版及公众号准备。稳定业务规则集中在一个入口，按任务加载五份参考，避免将单篇文章的材料和临时偏好变成永久规定。

依据当前代码核实了以下事实：

- `content/` 是实际 Obsidian 库，文章是 `content/posts/.../index.md`。
- Hugo 封面走全局 `resources.Get`，正文图片可以是文章目录资源。
- 发布器 `wechat.cover` 优先于 `image`，`wechat.title/digest` 也覆盖网站字段。
- 发布器 `check` 即使发现错误也可能返回进程退出码 0，需要读 JSON。
- `build` 会覆盖 metadata 中的旧草稿结果。
- 当前公众号代码仅有 `draft/add`，没有更新与正式发布命令。
- 平台块只在发布器输出中过滤，Hugo 不过滤；图片上传扫描原文全部本地图。

## 独立对抗审查

只读审查者检查真实发布器与 layouts，并模拟标题备选、新资讯入库、旧公众号草稿更新、平衡预案转最终版以及文章目录封面五种场景。

首轮发现及修正如下。

| 风险 | 原问题 | 已落实的修正 |
| --- | --- | --- |
| P1 | 平台块可能泄漏到 Hugo 网站 | 配图和公众号参考明确写出过滤范围，不再建议以此隔离网站内容 |
| P1 | build 前丢失唯一远端草稿 ID | 将旧 metadata 核对与归档放在 build 前 |
| P1 | 更换跨平台封面却保留旧微信覆盖值 | 明确更新或移除 `wechat.cover`，验收最终有效封面 |
| P2 | 网站专用图仍会被微信上传扫描 | 明确按原始全文预检，不能承诺平台块隔离上传 |
| P2 | 最终平衡正文更新但微信标题/摘要仍称预案 | 将平台覆盖字段纳入版本转换验收 |
| P2 | 标题备选触发无必要的仓库上下文读取 | 总入口增加轻量分支，只涉及稿件时才读取仓库状态 |

复核结论是六项问题已在规则层面解决，未发现新增可确认的 P1/P2。代码层面的能力限制仍保留，Skill 正确揭示它们，不假称实现了更新 API 或平台隔离。

## 前向测试结果

模拟请求为“已有微信草稿，最终方案公布，更新原稿并同步原草稿，封面换为 source-3.webp，用户自己群发”。审查者推导的执行路径符合目标：

1. 定位原稿并保全旧 media_id；未锁定目标时不猜测。
2. 核验最终方案，在原文件更新，保留首次日期、URL 和用户修改。
3. 同时核对微信标题/摘要/封面/来源 URL。
4. 将指定封面放入网站 assets，并更新微信有效覆盖值。
5. 完成本地检查与预览，标记远端内容可能过期。
6. 当前 CLI 不支持更新原草稿，不调用 `wechat-draft` 新建替代品；有实际更新能力的连接工具时再核对远端状态后继续。

这次测试未执行网络发布，也不证明任何远端草稿已被更新。

## 文件与自动检查

- `SKILL.md` 主入口包含路由、轻量分支、授权边界和续接规则。
- 五份参考覆盖入库格式、资讯事实与口吻、月度平衡生命周期、配图路径/节奏、公众号准备/同步。
- 根 `AGENTS.md` 使项目新会话能找到本地 Skill，无需全局安装；没有把内容规则用于无关代码或 SEO 工作。
- 只读 `scripts/check-article.rb` 使用 Ruby 标准库完整解析 YAML，检查必要字段、带时区日期、日期顺序和网站/微信图片路径。它明确不证明事实正确、图片能解码或实际渲染正常。
- `scripts/test-check-article.rb` 在临时目录运行了 9 个测试、41 条断言，覆盖完整稿、缺封面、bundle 封面、微信独立封面、缺正文图片、YAML 日期、非法 YAML、无时区日期、非支持图片语法及远端封面限制，全部通过。
- skill-creator 的 `quick_validate.py` 通过。系统 Python 缺少 PyYAML，因此在 `/tmp/scbase-skill-validator` 隔离环境中安装验证依赖，不改变项目依赖。
- 已用《爆裂小队》关服稿和 2026 年 10 月最终平衡稿执行 ready 检查。均通过，平衡稿提示手机宽度表格与 `draft: false` 需人工确认；关服稿也通过现有发布器 check。

## 剩余边界

该 Skill 负责编辑工作流，不替代人工事实核验与视觉检查，也不修复发布器缺失的能力。对比图和公开公告配图仍需核对真实内容与来源。未公开的关服项目不能凭资料缺失补全名单。

后续根据实际使用中出现的新失败修正规则，不将每次临时编辑要求累积成全局禁令。若公众号更新成为频繁独立任务，再考虑拆出独立发布 Skill 或补充发布器能力。
