# 配图与手机排版

## 项目资源约定

正文图保存在文章目录，用 `![内容说明](filename.webp)` 引用。标准 Markdown 优先，兼容现有 Obsidian 嵌入语法。避免使用临时剪贴板路径或机器绝对路径，让文章移动、构建和后续手动处理时仍能找到素材。

网站封面 `image` 与正文图片使用不同的资源解析方式。当前 Hugo 模板通过 `resources.Get` 读取封面，`image: /images/<year>/<slug>.webp` 应对应 `assets/images/<year>/<slug>.webp`。文章目录中存在图片，不代表把它的相对文件名填入 `image` 就能显示网站封面。

用户选定文章目录图片作网站封面时，保留原图内容，复制到 assets 的适当位置并填写对应路径。保留真实扩展名，检查目标是否已被其他稿件使用，不覆盖共享素材。若用户只要求检查，先报告问题，不自行改稿。

保留稿件已有的平台兼容字段；更换封面涉及多个有效覆盖字段时，按用户指定范围一起检查，避免继续引用旧图片。具体目录映射以当前模板为准，不以过去会话的某个文件名为约定。

## 选择与核对素材

- 图片应帮助理解附近文字，选择与主题直接相关且清晰可辨的素材，优先用户指定素材和可核实来源。
- 用户要求采用参考文章配图时，核对正文图片，过滤广告、导航和推荐内容；相同画面按需去重，注明来源。
- 核对图片内容、身份、版本与正文是否一致，不只看文件名。用户给出排序依据时先读取原始目录和说明，不凭附件显示顺序重排。
- 保存可追溯的来源信息，不编造作者或署名。能访问素材不代表已获得所有用途的使用许可，按实际来源条件处理。
- 裁切、缩放或拼接以清晰、完整呈现信息为目标，避免拉伸和丢失关键部位。标注、标签及比较版式依本次用途决定，不规定统一样式。
- 用作事实证据的图片应保留可核对的原始内容，不能用生成图或内容改写后的图片冒充原始资料。

## 图文节奏

把图片放在它解释的内容附近，文字负责说明观察点、背景或结论，图片负责展示。多图时用相关分析穿插，避免大量图片集中堆放；不固定要求每节几张图、某种插入顺序或某种收尾形式。

封面与正文重复时检查实际显示效果，按阅读需要决定是否保留。尊重用户明确要求的配图，不为去重而擅自删图。不同输出平台需要特殊处理时先核实模板能力，不凭注释或文件命名猜测隐藏规则。

手机阅读优先使用短而完整的段落、清楚的标题层级和合适的列表。表格控制列数与文字长度；需要横向滚动才能读懂时，考虑拆表或改为项目段落。长英文名称、数字和单位不要造成断行歧义。

## 验证

检查本地引用存在、图片能解码，查看新增或替换的图片。需要排版验证时使用 Obsidian 或 Hugo 本地预览，检查手机与桌面上的文字、图像、表格和间距；Hugo 构建成功不等于封面和正文图实际可见。

本 Skill 只完成本地编辑与入库，公众号转换和上传由用户二次编辑后手动执行。
