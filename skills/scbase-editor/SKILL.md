# scbase 工作流 skill

> 这是皇室小蜜的个人站点 Scbase 以及其公众号皇室小蜜的写作工作流 skill。个人账号 IP 全称「皇室小蜜」，同步维护超级细胞资讯站 Scbae（http://scbase.cn) 以及 皇室小蜜 公众号。

工作流核心是把可核验的游戏信息整理成适合中文读者、可持续更新的文章，以 `content/posts/.../index.md` 为唯一正文源。工作终点是稿件入库并交给用户二次编辑，用户完成修改后手动执行 `pub` 同步公众号。先满足用户当前要求，检查事实、图片和格式。用户的明确要求高于默认习惯。

## 按任务读取

| 当前工作 | 读取的子流程 |
| --- | --- |
| 新稿入库、修改已有 Markdown | [Obsidian/Hugo](references/obsidian-hugo.md) |
| 选题、写稿、审校、结构或口吻修改 | [文章编辑](references/article-editing.md) |
| 皇室战争月度预案、最终平衡、实装修正 | [平衡调整](references/clashroyale-balance.md)，同时读取文章编辑 |
| 文章配图、封面资源或排版修改 | [配图排版](references/images-layout.md) |

这些是同一个 Skill 的按需子流程，不需要分别安装。仅改一段文字或图片位置时，读取目标稿件和相关规则即可，不加载全部参考文件，也不重新研究未变动的事实。

## 开始工作

只给标题备选、讨论结构或做材料核验时，使用用户材料与必要的事实规则，不执行入库流程、不修改文件。只有请求涉及仓库稿件才定位文件与检查 Git；会话里事实足够且不涉及新时效信息时，无需重新研究。

1. 确定目标稿件、游戏和本次交付范围。用户给出路径就使用该路径；未给路径时检索标题、slug、日期，存在多个合理候选再询问。不能把“最近修改的文章”自动当作目标。
2. 阅读现有文件及用户改动，检查 `git status`。更新原稿时保留 URL、首次日期和用户选定标题，除非本次明确要求修改。
3. 新稿先读用户提供的材料，与现行版本有关的事实再核对最新一手说明。把官方说法、已发生事实与作者推断区分清楚；依据所需子流程处理。
4. 写稿或修改后执行相称检查。小幅排版调整不必反复全站构建；新稿、Front Matter 或资源路径变化需要渲染验证。

中文长文使用环境中的 `human-writing`，按其要求按需读取参考；不用复制其全文进本 Skill。若该 Skill 不可用，仍可遵循这里的基本口吻与来源要求，不伪称已运行它的检查器。

## 交付边界

- “写入 Obsidian”“准备公众号稿”“后续同步”只完成本地稿件，新稿设 `draft: true`。交付后由用户二次编辑并手动运行 `pub`。
- 本 Skill 不运行 `pub` 或发布器，不上传素材、不管理远端草稿和同步记录。用户另行提出发布工具需求时，作为独立任务处理，不由入库流程自动触发；也不自动发布网站或 `git push`。
- “检查”“先验证”“给备选标题”只做所请求的检查或备选，不把判断自动写入文章。
- 用户指定素材或内容顺序时，核对原始文件和说明；展示顺序、文件名与正文编号不一致时，不自行猜测。
- 资讯默认第三方报道，攻略侧重可操作性，专题按材料展开。情绪、幽默、标题 hook 等服从当前选题和用户要求。

## 验收与续接

本地稿件可用下面的只读检查器辅助检查。它不验证事实、版权或网页实际渲染，不能代替编辑审阅。

```bash
ruby skills/scbase-editor/scripts/check-article.rb content/posts/<game>/<date>/<slug>/index.md
# 需要完整稿件检查时
ruby skills/scbase-editor/scripts/check-article.rb --stage ready content/posts/<game>/<date>/<slug>/index.md
```

完成后提供稿件绝对路径，说明入库及修改内容，有未验证事项就明确说明。跨会话续接所需的信息写进 [本地编辑记录](references/obsidian-hugo.md#跨会话状态)，不依靠聊天记忆；不生成公众号同步状态或要求发布权限。

## 规则维护

这里只保存跨文章适用的编辑习惯与项目约定。单篇的标题、情绪、章节次序、角色名单、素材名和特定图片处理方式留在该篇稿件或任务记录中。新增规则前先判断它是否能帮助不同选题；能归纳就写决策原则，不能归纳就不加入通用 Skill。反复出现且有独立事实校验需求的工作可做按需专题流程，不默认加载。
